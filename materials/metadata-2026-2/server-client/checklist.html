수업 준비 체크리스트

가비아 클라우드 서버 refstd(Ubuntu 22.04)에 실습용 웹 서버를 따로 둡니다. 실습 파일은 /srv/class-lab 폴더에만 두고, 8080번 문에서 PHP 내장 웹 서버가 돌게 합니다. 참고문헌 체크 서비스의 설정 파일과 데이터베이스는 건드리지 않습니다. 체크 표시는 이 브라우저에만 기억됩니다.

지킬 것 서버 비밀번호·접속 키는 이 페이지, 슬라이드, 채팅, 파일, 화면 공유 어디에도 띄우지 않습니다. FileZilla는 ‘비밀번호 묻기’로 두고 수업 전에 미리 접속해 둡니다. 요금이 드는 변경(서버 사양, 새 서버, 공인 IP 추가)은 이 실습에 필요 없습니다.
1주 전 준비 수업 당일 시연 순서 학생 실습실 수업 뒤 문제 해결 주소 QR 만들기

1. 수업 1주 전 준비 (약 40분)

  • 서버 접속 창 열기. 가비아 콘솔 → 컴퓨팅 → 서버 → refstd → 기본 정보의 [서버 접속]. 로그인 계정과 비밀번호는 [서버 접속 비밀번호 발급]에서 받은 것을 씁니다.
  • 서버 상태 점검(읽기만 함). 아래 한 줄을 붙여 넣고 Enter. 아무것도 설치하거나 바꾸지 않습니다. 나온 결과를 Claude에게 보여 주면, 8080번 문이 비어 있는지와 기존 서비스와 겹치는 것이 없는지 함께 확인합니다. 
    curl -fsSL https://parkjuhyun-jnu.github.io/materials/metadata-2026-2/server-client/class-lab/setup/check.sh | bash
  • 실습 웹 서버 설치(한 번만). 우분투 기본 저장소에서 php-cli, php-sqlite3, php-mbstring, php-zip, sqlite3, unzip과 아카이빙 실습용 ffmpeg, exiftool, heif-convert를 설치하고, /srv/class-lab 폴더와 class-lab 서비스(8080번 문)를 만듭니다. 이미 설치했어도 같은 세 줄을 다시 실행하면 새 실습 파일로 바뀝니다(학생 자료가 든 /srv/class-lab/var는 그대로 둡니다). 점검에서 8080을 이미 쓰고 있었다면 마지막 줄 끝에 8081처럼 다른 번호를 붙입니다. 
    sudo apt-get install -y unzip
cd /tmp && curl -fsSLo class-lab.zip https://parkjuhyun-jnu.github.io/materials/metadata-2026-2/server-client/class-lab.zip
unzip -o class-lab.zip && sudo bash class-lab/setup/install.sh
    맨 끝에 처음 화면 200, 학생 실습실 200과 학생 입장 코드, 교수 코드가 나오면 됩니다. 두 코드를 적어 둡니다(교수 코드는 학생에게 알리지 않습니다). 처음에는 ffmpeg 설치 때문에 몇 분 걸립니다.
  • 가비아 방화벽에서 TCP 8080 열기. 가비아에서는 방화벽을 보안 그룹이라고 부릅니다. refstd의 [네트워크] 탭 → 네트워크 인터페이스 표의 보안 그룹(Default-SecurityGroup)을 눌러, 인바운드 규칙에 ‘TCP, 8080, 출발지 전체(0.0.0.0/0)’를 더합니다. 요금은 들지 않습니다. 같은 화면에서 22번(SFTP·SSH) 규칙이 어떻게 되어 있는지도 봐 둡니다.
  • 공인 IP 확인. refstd의 [네트워크] 탭에 있는 공인 IP를 적어 둡니다. 학생 주소는 http://공인IP:8080/입니다.
  • 폰으로 확인. 와이파이를 끄고 휴대폰 데이터로 http://공인IP:8080/에 들어가 처음 화면이 나오는지 봅니다. 학교 와이파이로도 한 번 더 봅니다(8080을 막는 망이 드물게 있습니다).
  • 내 컴퓨터에 실습 파일 풀기. class-lab.zip을 받아 바탕화면 등에 풉니다. 시연 때 FileZilla 왼쪽 창에서 이 폴더를 엽니다.
  • 파일 올리기 프로그램 준비. WinSCP가 이미 있으면 그것을 씁니다. 로그인 창의 [새 사이트]에 파일 프로토콜 SFTP, 호스트 이름 공인 IP, 포트 22, 사용자 이름 서버 접속 계정을 넣고 비밀번호 칸은 비운 채 [저장]합니다(접속할 때 묻습니다). 접속 뒤 오른쪽 창에서 /srv/class-lab/www로 갑니다. 아래 FileZilla 설명은 같은 일을 FileZilla로 할 때입니다. FileZilla Client(무료)를 쓴다면 [파일 → 사이트 관리자]에서 새 사이트를 만듭니다. 프로토콜 SFTP, 호스트 공인 IP, 포트 22, 로그온 유형 비밀번호 묻기, 사용자 서버 접속 계정(보통 root), 고급 탭의 기본 원격 디렉터리 /srv/class-lab/www. 한 번 접속해 step1 폴더가 보이는지 확인합니다. 22번 문이 방화벽에서 특정 IP로만 열려 있다면 강의실에서도 되는지 미리 봅니다.
  • 엑셀 확인. 풀어 둔 폴더의 data/권장도서_초등.xlsx를 열어 봅니다. 2,175권, 두 번째 시트에 출처가 있습니다.

  • 1단계 문장 되돌리기. 지난 시연에서 ‘오늘의 한 문장’을 바꿨다면 원래 파일을 다시 올려 둡니다.
  • 주소 띄우기. 아래 QR 만들기에 공인 IP를 넣어 화면에 띄웁니다.
  • 창 셋 열어 두기. ① 가비아 서버 접속 창, ② WinSCP 또는 FileZilla(접속한 상태), ③ 내 폰 화면(가능하면 화면 미러링). WinSCP를 쓰면 ①은 WinSCP 콘솔로 대신할 수 있습니다. 비밀번호가 보이는 창은 화면 공유에서 빼 둡니다.
  • 상태 확인. 폰으로 /step2/, /step3/에 들어가 ‘아직 없습니다’가 나오는지 봅니다.

서버 명령을 WinSCP 안에서 실행하기

가비아 서버 접속 창을 따로 열지 않고, 파일을 올리던 WinSCP에서 3단계 명령을 실행할 수 있습니다. 비밀번호를 다시 묻지 않습니다.

  1. WinSCP 메뉴 [명령(C)] → [터미널 열기(T)](Shift+Ctrl+T)를 누릅니다. ‘별도의 쉘 세션을 여시겠습니까?’가 나오면 [확인]을 누릅니다.
  2. ‘명령어 입력’ 칸에 아래를 넣고 [실행]을 누릅니다. 콘솔에 ‘들어간_책 2175’ 표와 연령별 표가 나오면 3단계 준비가 끝난 것입니다. 
    cd /srv/class-lab/data && sqlite3 books.db < load.sql
  3. SQL을 직접 보여 주려면 아래처럼 한 줄로 실행합니다. 이 콘솔은 한 번에 한 명령만 받으므로, sqlite3 books.db만 쳐서 안으로 들어가는 방식은 쓰지 않습니다. 
    sqlite3 /srv/class-lab/data/books.db "SELECT title FROM book WHERE author LIKE '%권정생%';"
  4. 연습한 뒤나 수업 직전에 되돌릴 때도 같은 칸에서 실행합니다. 
    bash /srv/class-lab/setup/demo-reset.sh

root로 접속했다면 sudo는 빼도 됩니다. 콘솔에서 cd를 하면 WinSCP 오른쪽 창도 그 폴더로 옮겨 가니, 1단계 시연 전에는 오른쪽 창을 /srv/class-lab/www로 되돌려 둡니다.

안내 페이지의 ‘그림 자리’ 세 곳(FileZilla 올리기, 엑셀 CSV 저장, load.sql 실행 결과)은 수업 중 화면을 캡처해 Claude에게 주시면 넣겠습니다. 비밀번호와 공인 IP가 보이지 않게 잘라 주세요.

4. 학생 실습실 운영 (A 홈페이지, B SQL, C 아카이빙)

시연 뒤에 학생이 직접 하는 실습입니다. 학생은 서버 계정 없이 브라우저로 http://공인IP:8080/lab/에 들어갑니다. 학생 안내는 학생 실습실 안내 페이지에 있습니다.

  • 교수 화면 들어가기. /lab/ 화면 아래 ‘교수로 들어가기’에 교수 코드를 넣습니다. 교수 화면에서 학생 입장 코드를 보고 바꿀 수 있고, 학생 진도, 비밀번호 초기화, 학생 지우기, 새 학생 받기와 아카이브 올리기 열고 닫기, 함께 쓰는 DB 비우기, B 문제의 채점 SQL을 봅니다.
  • 미리 한 번 해 보기. 연습용 아이디(예: test01)로 들어가 A의 할 일 하나, B1 문제 하나, C에 library-shelf.jpg 올리기를 해 봅니다. C 자료 화면의 보존 기록에 ‘기술 메타데이터 추출 성공’과 ‘이용본 만들기 성공’이 나오면 ffmpeg와 exiftool이 제대로 돈 것입니다. 끝나면 교수 화면에서 그 아이디를 지웁니다.
  • 수업 시간에 띄울 것. 주소 http://공인IP:8080/lab/와 학생 입장 코드. 학생이 모두 들어오면 교수 화면에서 ‘새 학생 받기 닫기’를 누르면 다른 사람이 새로 들어오지 못합니다.
  • 진도 받기. 교수 화면의 [진도 CSV 내려받기]와 [아카이브 메타데이터 CSV]가 엑셀에서 바로 열립니다. A는 할 일 일곱 개, B는 29문제, C는 자료 수와 메타데이터 여섯 칸을 다 단 자료 수입니다.
정해 둔 한도값
A 홈페이지한 사람 50MB, 파일 하나 20MB. PHP 파일은 실행하지 않고 글자로 보여 줌
B SQL한 번에 5초, 결과 300줄, 내 DB 약 20MB. 함께 쓰는 DB는 한 번에 20건까지 넣기
C 아카이브한 사람 20건, 파일 하나 100MB. 영상 이용본은 앞 60초, 소리 이용본은 앞 10분

한도는 /srv/class-lab/lib/app.php 맨 위에서 바꿉니다. 학생 20명이 C 한도를 다 쓰면 원본과 사본을 합쳐 최대 약 80GB가 들지만, 실제로는 폰 사진과 짧은 영상이라 훨씬 적습니다. 교수 화면 위쪽에 쓰는 공간과 남은 공간이 나옵니다. 모자라면 ‘올리기 닫기’를 누릅니다.

5. 수업 뒤

  • 복습용으로 열어 두기(선택). 학생이 수업 뒤에도 세 단계를 다시 볼 수 있게 하려면: 
    sudo bash /srv/class-lab/setup/demo-ready.sh
  • 비밀번호 점검. 수업 중 서버 비밀번호가 화면에 나왔다면 [서버 접속 비밀번호 발급]으로 바꿉니다.
  • 학기 끝에 끄기. 실습 서버만 끄고 지웁니다(참고문헌 체크 서비스는 그대로). 그다음 가비아 방화벽에서 8080 규칙을 지웁니다. 
    sudo bash /srv/class-lab/setup/uninstall.sh --files
    --files는 학생 홈페이지, 내 DB, 아카이브 자료까지 지웁니다. 먼저 교수 화면에서 진도와 메타데이터 CSV를 받아 두고, 학생에게 남길 자료를 내려받으라고 미리 알립니다.

6. 문제 해결

증상먼저 볼 것고치는 법
폰에서 안 열림 (오래 돌다 실패)가비아 방화벽의 8080 규칙인바운드 TCP 8080을 엽니다. 서버 안에서 curl -I http://localhost:8080/이 200이면 서버는 정상이고 방화벽 문제입니다.
서버 안에서도 안 열림sudo systemctl status class-labsudo systemctl restart class-lab. 계속 실패하면 sudo journalctl -u class-lab -n 30 결과를 Claude에게 보여 주세요.
학교 와이파이에서만 안 됨휴대폰 데이터로는 되는지학교망이 8080을 막는 경우입니다. 학생에게 데이터로 접속하게 하거나, 80번 문을 쓰도록 바꾸는 방법을 Claude와 상의합니다(기존 서비스 설정을 봐야 합니다).
2단계가 계속 ‘아직 없음’FileZilla 오른쪽 창의 위치와 파일 이름/srv/class-lab/www/step2/books.csv여야 합니다. 이름이 books (1).csv, Books.csv면 안 됩니다.
2단계 글자가 깨짐엑셀에서 고른 형식‘CSV(쉼표로 분리)’가 아니라 ‘CSV UTF-8(쉼표로 분리)’로 다시 저장합니다.
3단계가 계속 ‘아직 없음’ls -l /srv/class-lab/databooks.db가 없으면 cd /srv/class-lab/data 후 sudo sqlite3 books.db < load.sql을 다시 실행합니다.
load.sql에서 ‘no such file’지금 위치cd /srv/class-lab/data를 먼저 해야 books.csv를 찾습니다.
FileZilla 접속 실패22번 문 방화벽 규칙, 계정 이름방화벽에서 22번이 강의실 IP에 열려 있는지 봅니다. 급하면 1단계 시연은 서버 접속 창에서 sudo nano /srv/class-lab/www/step1/index.html로 고치고(저장 Ctrl+O, 나가기 Ctrl+X), 2단계는 demo-ready.sh로 대신합니다.
FileZilla에서 ‘권한 거부’접속 계정/srv/class-lab는 root 소유입니다. root가 아닌 계정이라면 sudo chown -R 계정이름 /srv/class-lab/www로 그 계정이 쓸 수 있게 합니다.
학생이 ‘수업 코드가 맞지 않습니다’교수 화면의 학생 입장 코드코드를 다시 띄웁니다. 10분 안에 열 번 틀리면 그 접속 주소는 10분 동안 막힙니다(같은 와이파이를 쓰는 학생이 함께 막힐 수 있음).
학생이 비밀번호를 잊음교수 화면의 학생 표[비밀번호 초기화]를 누르면 학생이 다음에 넣는 네 자리가 새 비밀번호가 됩니다.
C에서 ‘도구 없음’, 이용본이 안 생김bash /srv/class-lab/setup/check.sh의 ffmpeg, exiftool 줄설치 세 줄을 다시 실행합니다. 그 자료는 자료 화면의 [다시 처리]로 다시 돌립니다.
C에서 ‘처리 중’이 오래감영상 길이긴 영상은 이용본을 만드는 데 1~2분 걸리고, 자료는 한 번에 하나씩 처리합니다. 5분이 넘으면 sudo systemctl restart class-lab 뒤 [다시 처리]를 누릅니다.
큰 영상이 안 올라감파일 크기100MB가 넘으면 받지 않습니다. 폰에서 30초 안쪽으로 찍게 합니다.

8. 무엇을 어디에 두었나

서버 위치내용
/srv/class-lab/www/웹 루트. index.html, style.css, step1/, step2/(search.js, 시연 때 books.csv), step3/(index.php, api.php, db.php)
/srv/class-lab/data/웹 루트 바깥. 권장도서_초등.xlsx, books.csv, load.sql, 시연 때 생기는 books.db
/srv/class-lab/www/lab/학생 실습실 화면(들어가기, A 홈페이지, B SQL, C 아카이브, 교수 화면)
/srv/class-lab/lib/웹 루트 바깥. 실습실 프로그램(로그인, 학생 홈페이지 내보내기, SQL 실행과 권한, 문제와 채점 기준, 아카이브 처리)
/srv/class-lab/samples/C 아카이빙 보기 파일. 설치 때 var/samples로 복사하고, 사진 두 장과 녹음으로 library-tour.mp4를 만듭니다.
/srv/class-lab/var/학생 자료(www-data 소유, 다시 설치해도 그대로). settings.json(입장 코드), lab.db(학생, 진도, 아카이브 기록), catalog.db, shared.db, sites/, mydb/, archive/, backup/
/srv/class-lab/setup/check.sh(점검), install.sh(설치), lab-init.php(실습실 준비, --codes로 코드 바꾸기), demo-reset.sh, demo-ready.sh, uninstall.sh
/etc/systemd/system/class-lab.service실습 웹 서버 서비스. www-data 계정으로 돌고, 서버를 다시 켜도 자동으로 시작합니다.

PHP 내장 웹 서버는 수업 시연처럼 작은 쓰임을 위한 것입니다. 수강생 수십 명이 동시에 쓰는 정도는 넉넉하지만, 학기가 끝나면 끄는 것을 권합니다. 실습 파일은 class-lab.zip 한 묶음이며, 각 파일 첫머리에 하는 일을 적었습니다.
