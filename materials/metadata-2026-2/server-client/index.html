서버와 클라이언트: 어린이 권장도서 찾기

인터넷에 있는 ‘서버’에 파일을 올리고, 내 폰으로 들어가 봅니다. 같은 일, 곧 (사)어린이도서연구회가 고른 초등학생용 책 2,175권에서 원하는 책 찾기를 세 가지 방법으로 만들어 보면서 누가 일하는지를 비교합니다. 서버가 무엇인지 몰라도 괜찮습니다. 처음부터 차례로 설명합니다.

실습 순서로 바로 가기 실습 파일 받기 (zip) 교수용 준비 체크리스트
먼저 알아 둘 말 요청과 응답 URL과 웹 루트 데이터베이스 실습 1 HTML 한 장 실습 2 브라우저 검색 실습 3 서버 검색 누가 일했나 확인 문제
실습 전에 폰이나 노트북 하나만 있으면 됩니다. 설치할 것도, 가입할 것도 없습니다. 학교 와이파이든 휴대폰 데이터든 상관없습니다. 서버 주소(예: http://서버주소:8080/)는 수업 시간에 교수님이 화면에 띄웁니다. 서버에 파일을 올리는 일은 교수님이 화면으로 보여 주고, 여러분은 폰으로 들어가 무엇이 바뀌었는지 확인합니다.

먼저 알아 둘 말

서버는 부탁을 받으면 무언가를 내어 주는 컴퓨터(또는 프로그램)이고, 클라이언트는 부탁하는 쪽입니다. 웹에서는 여러분 폰의 브라우저(크롬, 사파리)가 클라이언트이고, 이번 실습에서는 가비아에서 빌린 컴퓨터가 서버입니다.

서버라고 해서 특별하게 생긴 기계는 아닙니다. 세 가지만 갖추면 어떤 컴퓨터든 서버가 될 수 있습니다. ① 늘 켜져 있고, ② 인터넷 어디서든 찾아올 수 있는 주소(공인 IP)가 있고, ③ 부탁을 기다리는 프로그램(웹 서버)이 돌고 있으면 됩니다. 교수님 노트북은 수업이 끝나면 꺼지고 학교 안쪽 망에 있어 밖에서 찾아오기 어렵습니다. 그래서 가비아의 클라우드 서버(인터넷 회사의 건물에서 24시간 켜져 있는 리눅스 컴퓨터)를 빌려 씁니다.

도서관으로 생각해 보기

클라이언트 = 이용자

원하는 것을 말하고 받아 갑니다. 받은 책을 어떻게 읽을지(화면을 어떻게 그릴지)는 이용자 몫입니다.

서버 = 대출 데스크와 서고

문을 열어 두고 기다리다가, 신청이 오면 서고에서 꺼내 건넵니다. 이용자가 누구든 같은 규칙으로 일합니다.

요청과 응답 = 신청서와 건네받은 책

“이 책 주세요”가 요청, 건네받은 책(또는 “그런 책은 없습니다”라는 쪽지)이 응답입니다.

URL = 도서관 위치 + 청구기호

어느 도서관의, 어느 서가의, 어느 책인지를 한 줄로 적은 것입니다.

웹 루트 = 개가식 서가

이용자가 직접 찾을 수 있게 열어 둔 서가입니다. 직원만 들어가는 보존 서고(웹 루트 바깥)는 주소로 열 수 없습니다.

데이터베이스 = 목록(카탈로그)

책마다 같은 칸(서명, 저자, 출판사…)으로 정리한 기록입니다. 사서가 목록을 뒤져 찾아 주는 것이 3단계의 서버입니다.

요청과 응답

폰 주소창에 주소를 넣고 이동을 누르면, 아래 일이 1초도 안 되는 사이에 일어납니다. 이 약속(어떻게 부탁하고 어떻게 답하는지)을 HTTP라고 부릅니다. 주소가 http://로 시작하는 까닭입니다.

내 폰클라이언트
(브라우저)
요청: “/step1/ 주세요” 응답: 200 OK + HTML 파일
가비아 서버웹 서버 프로그램
(8080번 문에서 기다림)
  1. 요청: 브라우저가 주소를 읽고 그 서버에 “이 경로의 파일을 주세요”라고 보냅니다.
  2. 처리: 서버가 요청을 받아 해당 파일을 찾습니다. 3단계에서는 여기서 프로그램(PHP)을 돌려 데이터베이스를 찾아봅니다.
  3. 응답: 서버가 결과를 돌려보냅니다. 맨 앞에 상태 번호를 붙입니다. 200은 ‘잘 찾았음’, 404는 ‘그런 파일 없음’입니다.
  4. 그리기: 브라우저가 받은 HTML을 읽어 화면을 그립니다. HTML 안에 CSS·JavaScript·그림 파일이 적혀 있으면 그것도 하나씩 다시 요청합니다.

실습 주소를 부분별로 나누면 이렇습니다. URI, URL, URN 참고 페이지에서 본 모양과 같고, 이번에는 포트가 하나 더 있습니다.

데이터베이스

데이터베이스(DB)는 같은 모양의 기록을 많이 모아 두고, 빠르게 찾고 고칠 수 있게 관리하는 저장소입니다. 3강에서 브라우저 실습실로 다룬 작은 도서관 DB가 바로 그것입니다. 이번 실습도 같은 종류(SQLite)를 씁니다. 다른 점은 DB가 내 브라우저가 아니라 서버 안에 있다는 것입니다. 여러분 폰은 DB 파일을 받지 못하고, 서버의 프로그램(PHP)에게 “이런 책 찾아 줘”라고 부탁만 할 수 있습니다.

엑셀 목록이 DB에 들어가는 길은 이렇습니다. 엑셀의 머리글(한글)과 DB의 열 이름(영문)이 짝을 이루는 것도 보세요. 메타데이터 수업에서 말하는 요소 대응(크로스워크)과 같은 일입니다.

엑셀 머리글번호책이름지은이출판사펴낸해쪽수연령갈래연구회링크

엑셀(.xlsx) → ‘CSV UTF-8’로 저장(books.csv, 쉼표로 칸을 나눈 글자 파일) → 서버에 올림 → sqlite3 프로그램이 load.sql을 실행해 book 테이블에 넣음. 이 순서를 실습 3에서 교수님이 보여 줍니다.

실습 순서

실습은 모두 약 60분. 교수는 교수님이 화면으로 보여 주는 일, 나는 여러분이 폰으로 하는 일입니다.

실습 1 · 15분

HTML 한 장 받아 보기: 서버는 파일을 건네준다

  1. 교수서버 접속 창에서 웹 루트 폴더 /srv/class-lab/www 안의 파일 목록을 보여 줍니다. 이 폴더가 곧 사이트입니다.
  2. 나폰 브라우저 주소창에 교수님이 띄운 주소 http://서버주소:8080/을 그대로 넣습니다. 검색창이 아니라 주소창에 넣어야 합니다. QR 코드가 있으면 카메라로 찍어도 됩니다.
  3. 나처음 화면에서 1단계를 누릅니다. ‘지금 주소 뜯어 보기’에서 서버·포트·경로가 무엇인지 확인합니다.
  4. 교수내 컴퓨터에서 step1/index.html을 메모장으로 열어 ‘오늘의 한 문장’을 바꾸고 저장한 뒤, FileZilla로 서버의 같은 자리에 다시 올립니다.
  5. 나아무것도 누르지 말고 화면을 봅니다. 바뀌었나요? 이제 새로고침을 누릅니다. 이번에는요?
  6. 나주소 끝을 /step1/없는파일.html로 바꿔 들어가 봅니다. 서버가 무엇이라고 답하나요? (404)
확인할 것서버는 파일 내용을 바꾸지 않고 그대로 건넸습니다. 새로고침해야 바뀐 것은, 폰이 다시 요청해야 서버가 새 파일을 주기 때문입니다. 서버는 먼저 연락하지 않습니다. 언제나 클라이언트가 먼저 부탁합니다.
실습 2 · 20분

목록을 통째로 받아 내 폰에서 찾기: 클라이언트가 일한다

  1. 나처음 화면에서 2단계를 누릅니다. ‘목록 파일이 아직 서버에 없습니다’가 나옵니다.
  2. 교수엑셀 파일 권장도서_초등.xlsx을 열어 보여 줍니다. 한 줄이 책 한 권, 한 칸이 요소 하나입니다. ‘다른 이름으로 저장 → CSV UTF-8(쉼표로 분리)’로 books.csv를 만들고 메모장으로 열어 쉼표로 나뉜 글자임을 보여 줍니다.
  3. 교수FileZilla로 books.csv를 서버의 /srv/class-lab/www/step2/에 올립니다.
  4. 나새로고침합니다. ‘서버에서 받은 양’과 ‘내 폰에 들어온 책’ 수를 적어 둡니다.
  5. 나지은이에 권정생을 넣어 찾고, 연령을 9세부터로 좁혀 봅니다. 글자를 넣을 때마다 바로 결과가 바뀝니다.
  6. 나폰을 비행기 모드로 바꾸고(와이파이도 끄고) 다른 말로 다시 찾아봅니다. 찾아지나요? 끝나면 비행기 모드를 끕니다.
확인할 것서버는 세 파일(index.html, search.js, books.csv)을 건넸을 뿐입니다. 찾는 일은 폰 안의 JavaScript가 했습니다. 그래서 인터넷이 끊겨도 찾아집니다. 대신 목록이 1만 권, 100만 권이 되면 어떨까요? 그리고 누구나 /step2/books.csv 주소로 목록 전체를 받아 갈 수 있습니다.
실습 3 · 25분

서버에게 찾아 달라고 하기: 서버가 일한다

  1. 나처음 화면에서 3단계를 누릅니다. ‘데이터베이스가 아직 없습니다’가 나옵니다.
  2. 교수가비아 콘솔의 서버 접속 창에서 아래 두 줄을 실행합니다. load.sql이 book 테이블을 만들고, books.csv를 읽어 넣고, 몇 권 들어갔는지 표로 보여 줍니다. 
    cd /srv/class-lab/data
sudo sqlite3 books.db < load.sql
  3. 나새로고침합니다. 2단계처럼 권정생, 9세부터로 찾습니다. 이번에는 찾기 단추를 눌러야 결과가 바뀝니다. 왜일까요?
  4. 나주소창을 봅니다. ?q=권정생&age=9세부터처럼 찾을 말이 주소에 붙어 있습니다. 주소의 권정생을 다른 이름으로 직접 고쳐 들어가 봅니다.
  5. 나‘서버가 데이터베이스에 보낸 SQL 보기’를 펼칩니다. 3강에서 쓴 SELECT … WHERE … LIKE … ORDER BY … LIMIT와 같은지 봅니다.
  6. 나‘내 폰이 받은 양’을 2단계와 비교합니다. 그리고 비행기 모드로 바꿔 다시 찾아봅니다. 이번에는요?
  7. 나(더 해 보기) ‘같은 결과를 JSON으로 받기’를 엽니다. 2강에서 본 API와 같은 모양입니다. 사람이 아니라 다른 프로그램이 받아 쓰는 응답입니다.
확인할 것이번에는 폰이 찾을 말만 보내고, 서버의 PHP 프로그램이 SQL로 DB에 물어 찾은 책만 HTML로 만들어 보냈습니다. 받는 양이 작고, 목록이 커져도 폰은 힘들지 않습니다. 대신 인터넷이 끊기면 찾을 수 없고, 손님이 많아지면 서버가 바빠집니다. DB 파일은 웹 루트 바깥에 있어 아무도 통째로 받아 갈 수 없습니다.

확인 문제

1. 내 폰으로 네이버에 들어갈 때, 클라이언트와 서버는 각각 무엇인가요?

클라이언트는 내 폰의 브라우저(또는 네이버 앱), 서버는 네이버 회사가 운영하는 컴퓨터들입니다. 같은 폰도 다른 폰에게 파일을 내어 주는 프로그램을 돌리면 서버가 될 수 있습니다. 서버와 클라이언트는 기계 종류가 아니라 맡은 역할의 이름입니다.

2. 교수님이 파일을 바꿔 올렸는데 내 화면이 그대로입니다. 왜일까요?

서버는 먼저 연락하지 않습니다. 내 폰이 다시 요청(새로고침)해야 새 파일을 받습니다. 새로고침해도 그대로라면 브라우저가 예전에 받은 파일을 저장해 두었다가(캐시) 다시 쓴 것일 수 있습니다.

3. http://서버주소:8080/step2/books.csv를 주소창에 넣으면 어떻게 되나요? /data/books.db는요?

books.csv는 웹 루트 안에 있으므로 목록 파일 전체가 내려받아집니다. 2단계 방식의 약점입니다. books.db는 웹 루트 바깥(/srv/class-lab/data)에 있으므로 주소가 없고, 404가 나옵니다.

4. 3단계에서 찾을 말 권정생은 어떤 길로 서버에 갔나요?

주소의 질의 부분(?q=권정생)에 붙어 요청과 함께 갔습니다. 서버의 PHP가 그 값을 꺼내 SQL의 LIKE 조건에 넣었습니다. 그래서 주소만 고쳐도 다른 검색이 되고, 이 주소를 그대로 친구에게 보내면 같은 검색 결과를 볼 수 있습니다.

5. 1단계와 3단계 화면은 모두 ‘서버에서 받은 HTML’입니다. 무엇이 다른가요?

1단계 HTML은 서버 폴더에 미리 만들어 둔 파일이라 누가 언제 요청해도 같습니다(정적). 3단계 HTML은 요청이 올 때마다 PHP가 그 자리에서 만든 것이라 찾을 말과 시각에 따라 달라집니다(동적). 3단계 화면 아래의 ‘이 화면은 서버가 … 에 만들었습니다’ 시각이 새로고침할 때마다 바뀌는 것으로 확인할 수 있습니다.

6. 엑셀 머리글 ‘책이름’을 DB에서는 title이라고 부릅니다. 메타데이터 수업의 어떤 개념과 닮았나요?

서로 다른 두 양식의 요소를 짝짓는 요소 대응(크로스워크)입니다. 더 나아가 title을 더블린 코어의 dc:title로, author를 dc:creator로 짝지으면 다른 기관과 이 목록을 주고받을 수 있습니다. 쪽수 칸에 ‘각 136’처럼 숫자가 아닌 값이 섞여 있는 것도 살펴보세요. 값을 어떻게 적을지 정하는 내용 규칙이 왜 필요한지 보여 줍니다.

실습 파일

서버에 올린 파일을 모두 내려받아 열어 볼 수 있습니다. HTML·JavaScript·PHP·SQL 파일 곳곳에 무엇을 하는 부분인지 한국어 설명을 달았습니다.

  • class-lab.zip: 실습 파일 전체 (웹 루트 www, 목록 data, 서버 설치 스크립트 setup)
  • 권장도서_초등.xlsx: 엑셀 목록 2,175권 (두 번째 시트에 출처와 설명)
  • books.csv: 엑셀을 ‘CSV UTF-8’로 저장한 것. DB Browser for SQLite에서 ‘파일 → 가져오기 → CSV 파일에서 테이블’로 넣으면 내 컴퓨터에서도 같은 DB를 만들어 볼 수 있습니다.
  • load.sql: 서버에서 books.csv를 DB에 넣을 때 쓴 SQL (서버의 sqlite3 프로그램용)
